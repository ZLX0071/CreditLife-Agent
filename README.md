# CreditLife-Agent — 覆盖信贷全生命周期的多 Agent 智能客服系统

> 从通用电商客服多 Agent 架构出发，改编为银行信用卡客服场景，并进一步深入**消费信贷贷后与催收合规**业务——形成"贷前申请 → 用卡服务 → 账单还款 → 逾期协商 → 贷后合规"的全生命周期覆盖。
> 场景语料、分层评测集、合规评测维度、危机干预与多项工程修复为本人二开内容（见 [改动清单](#改动清单)）。

## 项目定位

CreditLife-Agent 不是单纯的聊天机器人，而是把以下能力串成闭环的客服系统：

- **细粒度意图识别**：LLM + Embedding + 规则三路打分，18 类意图、意图组归一化、结构化实体提取
- **路由驱动的多 Agent 编排**：账单服务 / 技术支持 / 综合接待 / 人工交接四类 Agent，主辅协作、降级兜底、意图+关键词双信号检测复合问题
- **双业务线 Skill 体系**：信用卡与贷后两套话术规范按关键词精确分流注入，互不污染
- **意图驱动 RAG**：15 篇信贷业务语料（息费规则、分期、争议处理、催收红线、征信异议）向量化检索，回答有据可依
- **三级记忆**：Redis 工作记忆 + 会话摘要 + ChromaDB 情景记忆与用户画像，自动压缩防上下文膨胀
- **工具可靠性治理**：TTL 缓存、熔断器、fallback 降级、查询改写、LLM 重排、缓存主动失效
- **合规优先**：催收红线手册（GB/T 45251-2025 口径）、危机干预分支（心理援助热线转介）、绝对化表述拦截
- **LLM-as-Judge 端到端评测**：相关性/准确性/完整性/有用性/**合规性**五维评分 + 基线回归 + 双 Judge 校准 + 人工抽标

## 为什么是"信贷全生命周期"

信用卡客服规则密集（息费、分期、征信），合规红线清晰；而贷后与催收是监管风暴眼（GB/T 45251-2025 国标、中银协 2026 指引），对抗场景真实且极端（诱导违规、轻生威胁、第三人催收）。一套系统覆盖两条高风险业务线，评测重点从"答得好不好"扩展到"**答得合不合规、危机处理对不对**"。

## 技术栈

| 层 | 技术 | 用途 |
|----|------|------|
| 应用框架 | Python 3.12 / FastAPI / Pydantic | API 服务与数据契约 |
| LLM | 通义千问 qwen-plus（Anthropic 协议兼容端点） | 意图识别、Agent 回复、记忆压缩、Judge |
| 多 Agent 编排 | 自研 AgentOrchestrator（规则打分路由 + 主辅协作） | 路由、并行、升级 |
| 检索 | ChromaDB（向量数据库）+ 查询改写 + LLM 重排 | RAG 知识库 |
| 记忆 | Redis（工作记忆 TTL 24h）+ ChromaDB（情景记忆/用户画像） | 三级记忆 |
| 规则注入 | 动态 Skills（Markdown 热加载） | 业务规范与合规护栏 |
| 监控 | Prometheus + 自研 PerformanceMonitor（路由降权） | 在线健康度 |
| 评测 | LLM-as-Judge + 回归基线 + 双 Judge 校准脚本 | 质量闭环 |
| 部署 | Docker Compose（app/Redis/ChromaDB/Prometheus/Nginx/调试前端） | 一键全栈 |

## RAG 设计（重点）

```
用户问题
→ 意图判断（业务类问题才检索，寒暄/转人工跳过）
→ Agent 决策调用 knowledge_search 工具（强制策略：业务事实先检索后回答）
→ LLM 查询改写成多角度子查询
→ 多子查询并行召回 ChromaDB（向量检索）
→ 合并去重 → LLM 重排 → Top-K 注入 Agent 上下文
→ 工具层治理：TTL 缓存(300s) / 熔断器 / fallback 降级 / 知识库更新即清缓存
```

## 记忆与缓存

| 层 | 存储 | 内容 | 策略 |
|----|------|------|------|
| 工作记忆 | Redis | 当前会话最近 20 条消息 | TTL 24h；达 15 条自动压缩，保留最近 5 条 |
| 会话摘要 | Redis | 压缩摘要 | 同会话下次请求直接拼入 prompt |
| 情景记忆 | ChromaDB episodic | 压缩摘要+元数据 | 跨会话语义检索相关历史 |
| 用户画像 | ChromaDB user_profile | 偏好与关键实体 | 每轮异步提炼 |
| 检索缓存 | 进程内 TTL Cache | 相同查询的召回结果 | 300s 过期；**知识库更新时主动失效** |

### 评测结果（2026-09-27，qwen-plus）

> 50 条信用卡单线版两轮实测（[评测报告](docs/评测报告.md)）：意图准确率 **90.0%**（Macro-F1 0.844）、合规对抗 4/4 满分拒绝、回归 0 退化、RAG 触发率 0%→修复后正常。
> 94 条双线版最终实测（qwen-plus-latest）：对话五维均分 0.95，**合规 1.00**，通过率 96.6%，回归 0；
> 意图双口径：严格单标签 74.1%（卡线 93.3%）/ 意图组级 77.8%——贷后边界条目分析见评测报告；
> 双 Judge 校准（qwen-turbo 独立复评 20 样本）：合规维度一致率 100%，各维度偏差 ≤0.11；
> 20 条人工抽标表已生成（data/eval/人工抽标表.md），人工标注后回填人机一致率。

## 快速开始

```bash
# 1. 配置 .env（Anthropic 协议兼容的模型服务，示例为阿里云百炼 qwen）
cp .env.example .env

# 2. 一键全栈（含调试前端）
docker compose up -d --build

# 3. 浏览器对话（推荐，无需配置）
#    打开 http://localhost:5173 直接发消息，右侧面板显示意图/路由/耗时
#    Swagger 调试台：http://localhost:8000/docs

# 4. 冒烟
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"message":"我的信用卡最低还款会影响征信吗？","user_id":"u1","conv_id":"c1"}'

# 5. 评测（约 94 条用例，会消耗 LLM 额度；save_baseline=true 才写入回归基线存档）
curl -X POST http://localhost:8000/eval/run -H "Content-Type: application/json" \
  -d @data/eval/creditlife_eval_cases.json
```

## 改动清单（相对电商客服基线）

1. **场景改编**：5 个 Skill 话术规范（信用卡×2 + 贷后×2 + 共享技术）、15 篇业务语料、意图模板金融化（订单→办卡/放款进度、物流→卡片邮寄等语义映射）、4 类 Agent 角色契约适配信贷业务
2. **合规与安全**：LLM-as-Judge 新增 compliance 维度（含催收红线 15 条）；对话用例 `expected_behavior` 定向评判；EscalationAgent 危机干预分支（确定性代码，不依赖概率模型）
3. **评测工程**：94 条分层评测集 + 标注规范；双 Judge 校准脚本；`EVAL_JUDGE_MODEL` 独立配置
4. **工程修复与增强**：知识库播种从硬编码改为目录化（`KNOWLEDGE_SEED_DIR`，语料与代码分离）；修复 ChromaDB 多条件 where 未用 `$and` 的缺陷；修复 RAG 工具引导策略缺失导致的检索 0 触发；修复辅助 Agent 浮动门槛与复合问题兜底缺失；修复 Pattern 跨意图组修正；知识库更新后检索缓存主动失效

## Roadmap

- 流式输出（SSE）：端到端延迟不变，首字 <2s——当前长回答非流式，感知等待 15s+（归因见[指标体系与成本模型](docs/指标体系与成本模型.md) §2）
- 回答长度规范（Skill 约束"先结论、≤300 字"）：输出 token 减半，延迟与成本双降，需重评测确认完整性不回退
- 意图识别与查询改写并行化 / 高置信意图跳过重排：RAG 命中场景 -3~5s
- 意图识别切轻量模型（qwen-turbo）：延迟+成本双降，采用前需重跑意图评测集
- Skills 关键词触发的语义匹配兜底（当前为字符串包含匹配，口语化表达可能漏召回）
- Embedding 分支接入真正的中文语义向量模型（当前为本地字符 n-gram 哈希，非真语义匹配）
- 完整对话记录持久化（当前仅保留工作记忆/摘要/画像，用户无法回溯全量历史）
- Agent 间依赖传递（当前复合问题并行处理、统一汇总，无上下游依赖链）
- 检索 Top-K 与重排策略的 trade-off 实验（k=3/5/8 对完整性与延迟的影响）

## 面试演示点

- **合规对抗**：连续发起"推荐稳赚理财 / 承诺洗白征信 / 指导套现 / 施压退息"，全部正确拒绝并给合规替代路径
- **危机干预**：发送轻生威胁话术，观察系统停止还款话题、转介心理援助热线、标记最高优先级转人工
- **双线分流**：同一句"还款"在信用卡语境与贷款语境命中不同 Skill 规范
- **评测闭环**：`/eval/run` 一键产出五维评分 + 回归检测，报告含 badcase 归因
