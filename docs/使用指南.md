# CreditLife-Agent 完整使用指南

> 本文档说明 CreditLife-Agent 的部署、启动、API 调用、调试前端、知识库使用、三层记忆查看、监控评测和常见排障。
> 面向第一次 clone 本仓库的人：跟着做，10 分钟内可以跑起完整系统并在浏览器里和 Agent 对话。

CreditLife-Agent 是一个覆盖信贷全生命周期的多 Agent 智能客服系统，核心链路为：

```
用户请求
-> FastAPI /chat
-> MemoryManager 读取 Redis 工作记忆 + ChromaDB 情景记忆 + 用户画像
-> IntentRecognizer 识别 18 类细粒度意图 + 意图组 + 结构化实体
-> AgentOrchestrator 路由到 账单服务 / 技术支持 / 综合接待 / 人工交接 Agent
-> SkillManager 按 消息关键词 + Agent 类型 匹配 双业务线 Skills（信用卡线 / 贷后线）
-> Agent 基于记忆 + 知识库 + 结构化实体 + Skills 调用 LLM 生成回复
-> 写入 Redis，并异步更新 ChromaDB 用户画像
```

除主对话链路外，系统还提供独立评测链路：

```
评测请求
-> FastAPI /eval/run
-> IntentEvaluator 计算 Accuracy / Macro-F1
-> EndToEndEvaluator 调用 Orchestrator 生成真实 Agent 回复
-> LLMJudge 从 相关性 / 准确性 / 完整性 / 有用性 / 合规性 五维评分
-> 与历史基线对比，输出 regressions 和 recommendations
```

## 1. 项目结构

```
CreditLife-Agent/
├── api/main.py                  # FastAPI 入口：/chat /search /knowledge /monitor /eval /trace
├── core/intent_recognizer.py    # 三路融合意图识别（LLM + Embedding + 规则）
├── core/skill_loader.py         # Skills 加载、解析、关键词匹配和 prompt 注入
├── agents/agent_orchestrator.py # 多 Agent 路由编排 + 危机干预前置分支
├── agents/tools.py              # 共享工具层（角色白名单约束）
├── memory/conversation_memory.py# Redis + ChromaDB 三层记忆管理
├── mcp/tool_manager.py          # 工具调用治理：缓存、熔断、降级、查询改写、重排
├── mcp/knowledge_base.py        # ChromaDB RAG 知识库
├── monitor/performance_monitor.py # Agent/工具在线监控与路由降权
├── evaluation/evaluator.py      # 端到端评测（含合规维度）
├── skills/                      # 可热加载的双业务线 Skills（信用卡 3 + 贷后 2）
├── data/demo_docs/              # 15 篇信贷业务语料（息费、分期、催收红线、征信异议等）
├── data/eval/                   # 94 条分层评测集 + 各轮评测结果 + 人工抽标表
├── frontend/dist/               # 调试前端控制台（随 compose 启动，localhost:5173）
├── docs/                        # 评测报告 / PRD / 竞品分析 / 技术亮点 / 架构图
├── docker-compose.yml           # Docker 全栈编排（6 个服务）
├── Dockerfile
├── requirements.txt
└── .env.example
```

## 2. 环境准备

### 2.1 必需依赖

- Docker + Docker Compose
- 一个 Anthropic 协议兼容的模型服务 API Key（默认示例为阿里云百炼 qwen，也可接 DeepSeek 等兼容端点）

### 2.2 配置 .env

```bash
cp .env.example .env
```

最少需要配置：

```
ANTHROPIC_API_KEY=your_api_key
```

如果使用阿里云百炼（Anthropic 兼容端点）：

```
ANTHROPIC_BASE_URL=https://dashscope.aliyuncs.com/apps/anthropic
ANTHROPIC_MODEL=qwen-plus-latest
ANTHROPIC_API_KEY=your_dashscope_key
```

评测 Judge 模型可独立配置（不配置则与主模型相同）：

```
EVAL_JUDGE_MODEL=qwen-turbo
```

Docker Compose 场景下，Redis 和 ChromaDB 的连接由 docker-compose.yml 覆盖为容器内地址，通常不需要手动改。Skills 默认从项目内 `./skills` 读取，可通过环境变量覆盖：

```
CREDITLIFE_SKILLS_DIR=./skills
CREDITLIFE_SKILLS_MAX_PROMPT_CHARS=8000
```

## 3. Docker Compose 全栈部署（推荐）

```bash
docker compose up -d --build
```

查看服务状态与健康检查：

```bash
docker compose ps
curl http://localhost:8000/health
```

启动后的端口：

| 服务 | 容器名 | 宿主机端口 | 用途 |
|------|--------|-----------|------|
| CreditLife API | creditlife-app | 8000 | 主 API 服务 |
| 调试前端 | creditlife-frontend | **5173** | 浏览器对话控制台 |
| Nginx | creditlife-nginx | 80 | 反向代理 |
| ChromaDB | creditlife-chromadb | 8001 | 向量数据库（知识库 + 长期记忆） |
| Redis | creditlife-redis | 6379 | 工作记忆 |
| Prometheus | creditlife-prometheus | 9090 | 监控数据 |

## 4. 调试前端控制台

打开 **http://localhost:5173**，无需任何配置（前端默认连接 `http://localhost:8000`）：

- **对话页**：像聊天一样发消息，右侧面板实时显示意图、置信度、Agent 路由、耗时、知识库是否命中、是否转人工，以及路由打分明细（`routing_reason`）。
- **知识库页**：检索知识条目、添加/上传文档、查看当前加载的 5 个 Skills 和解析状态。
- **评测页**：可视化触发 `/eval/run`。**注意：完整评测约 94 条用例，每条都会真实调用 LLM 和 Judge，会消耗模型 API 额度**——日常调试不要随手点。

## 5. Swagger 和接口总览

启动后浏览器访问 **http://localhost:8000/docs**，点击任意接口右侧 **Try it out**，填写参数后 **Execute** 直接调用。

常用调试顺序：

```
1. GET  /health            确认服务是否就绪
2. POST /chat              测试主对话链路
3. GET  /knowledge/stats   查看知识库是否已有数据
4. POST /knowledge/upload  上传知识文件
5. POST /search            测试知识库检索、查询改写和重排
6. GET  /monitor           查看 Agent 和工具运行指标
7. GET  /skills            查看当前已加载 Skills
8. POST /skills/reload     修改 Skill 文件后热加载
9. GET  /trace/tools       查看最近工具调用链路
10. POST /eval/run         运行端到端评测
```

### 5.1 接口总览

| 方法 | 路径 | 参数位置 | 作用 |
|------|------|---------|------|
| GET | /health | 无 | 健康检查，返回服务状态和 Agent 统计 |
| POST | /chat | JSON Body | 主对话接口：记忆读取 → 意图识别 → Agent 路由 → 回复生成 → 记忆写入 |
| GET | /monitor | 无 | Agent/工具统计、告警和优化建议 |
| GET | /metrics | 无 | Prometheus 指标文本 |
| POST | /search | Query 参数 | 知识库检索优化链路（查询改写 → 并行召回 → 合并去重 → LLM 重排） |
| GET | /skills | 无 | 当前加载的 Skills、适用 Agent、关键词 |
| POST | /skills/reload | 无 | 运行时重新扫描 Skill 目录（改规则无需重启） |
| POST | /knowledge/add | JSON Body | 批量导入文档到 ChromaDB（会主动失效检索缓存） |
| POST | /knowledge/upload | Form File | 上传 .txt / .md / .json 文件导入知识库 |
| GET | /knowledge/stats | 无 | 知识库文档片段总数 |
| GET | /trace/tool/{id} | 路径参数 | 单次请求的工具调用链路 |
| GET | /trace/tools | 无 | 最近工具调用链路列表 |
| POST | /eval/run | 可选 JSON Body | 运行意图识别 + 端到端对话评测（五维含合规） |

### 5.2 /chat 主对话接口

请求体：

```json
{
  "message": "信用卡分期手续费怎么算？",
  "user_id": "user_001",
  "conv_id": "session_001"
}
```

多轮对话只需保持同一个 `user_id` 和 `conv_id`，系统会从 Redis 读取当前会话最近消息、从 ChromaDB 读取相关历史和用户画像，拼成上下文传给 Agent。

关键返回字段：

| 字段 | 说明 |
|------|------|
| response | Agent 回复 |
| intent / intent_group | 细粒度意图 / 归一化意图组 |
| agent_type / agent_types | 主返回 Agent / 实际参与执行的 Agent 列表 |
| primary_agent / supporting_agents | 主处理 / 辅助 Agent（复合问题主辅协作） |
| routing_reason / routing_confidence | 路由原因（含各 Agent 领域分数）与置信度 |
| escalated | 是否触发升级/转人工 |
| knowledge_used | 本次回复是否注入知识库检索上下文 |
| entities | 结构化实体（卡号后四位、金额、日期、错误码等） |
| intent_source_scores | LLM / Embedding / Pattern 三路来源分数 |
| latency_ms | 端到端耗时 |

体验双业务线分流：

```bash
# 信用卡语境 —— 命中信用卡 Skills
{"message": "信用卡分期手续费怎么算？", "user_id": "d1", "conv_id": "c1"}
# 贷后语境 —— 命中贷后 Skills
{"message": "我逾期了，还能协商还款吗？", "user_id": "d2", "conv_id": "c2"}
```

容器日志可看到注入明细：`Skills 已注入: agent=... matched=... (keywords=...)`。

### 5.3 双业务线 Skills

Skills 是可热加载的业务规范文档，和知识库分工不同：**知识库回答"业务事实是什么"，Skills 约束"客服应该怎么处理、怎么措辞、什么不能做、什么时候升级"**。

| Skill | 文件 | 业务线 | 作用 |
|-------|------|--------|------|
| 银行卡综合服务接待规范 | skills/general_customer_service/ | 信用卡 | 首轮接待、信息澄清、分流、转人工 |
| 账单服务处理规范 | skills/billing_support/ | 信用卡 | 息费、分期、账单、还款争议 |
| 技术支持处理规范 | skills/technical_support/ | 通用 | App 故障、登录异常、安全边界 |
| 贷后还款与逾期协商规范 | skills/loan_billing_support/ | 贷后 | 逾期协商、减免话术边界、还款方案 |
| 借款咨询与催收投诉接待规范 | skills/loan_general_service/ | 贷后 | 催收投诉、暴力催收界定、合规接待 |

信用卡线与贷后线靠关键词精确切分、互不污染（例如"逾期/协商"只命中贷后线，"分期/账单"只命中信用卡线）。修改任意 SKILL.md 后调用 `POST /skills/reload` 热加载，无需重启服务。

## 6. 知识库使用

知识库由 `mcp/knowledge_base.py` 管理，底层为 ChromaDB collection `knowledge_base`。首次启动如为空，会自动导入 `data/demo_docs/` 下的 15 篇信贷业务语料（息费规则、分期、还款渠道、争议处理、催收红线、征信异议、冒名借款、法催调解等），约 23 个向量切片。

检索测试：

```bash
curl -X POST "http://localhost:8000/search?query=逾期协商需要什么材料&top_k=3"
```

批量导入 / 上传文件：

```bash
curl -X POST http://localhost:8000/knowledge/add \
  -H "Content-Type: application/json" \
  -d '{"documents": [{"title": "分期手续费公示", "content": "..."}]}'

curl -X POST http://localhost:8000/knowledge/upload -F "file=@your_doc.md"
```

长文档会切成约 500 字的片段写入 ChromaDB；导入/上传会**主动失效工具层 TTL 缓存**，保证后续检索拿到新内容（缓存默认 300s 过期）。

## 7. 三层记忆查看

| 层 | 存储 | 内容 | 策略 |
|----|------|------|------|
| 工作记忆 | Redis `wm:{user_id}:{conv_id}` | 当前会话最近消息 | TTL 24h；达 15 条自动压缩，保留最近 5 条 |
| 会话摘要 | Redis `summary:{user_id}:{conv_id}` | 压缩摘要 | 同会话下次请求直接拼入 prompt |
| 情景记忆 | ChromaDB `episodic` | 压缩摘要 + 元数据 | 跨会话语义检索相关历史 |
| 用户画像 | ChromaDB `user_profile` | 偏好和关键实体 | 每轮 /chat 后异步提炼 |

查看 Redis 工作记忆：

```bash
docker exec -it creditlife-redis redis-cli -a creditlife123
> LRANGE wm:user_001:session_001 0 -1
> TTL   wm:user_001:session_001
```

查看 ChromaDB collections（在应用容器内）：

```bash
docker exec -it creditlife-app bash
python - <<'PY'
import chromadb
client = chromadb.HttpClient(host="chromadb", port=8000)
for c in client.list_collections():
    print("-", c.name, "count=", c.count())
PY
```

注意：情景记忆只有当前会话消息数达到压缩阈值（15 条）后才写入，连续发 16 条以上消息再查看。

## 8. 监控

```bash
curl http://localhost:8000/monitor    # Agent/工具成功率、延迟、熔断状态、告警、优化建议
curl http://localhost:8000/metrics    # Prometheus 指标文本
```

Prometheus 控制台：http://localhost:9090

在线表现会反哺路由：表现差的 Agent 会被写回 `monitor_penalty`，降低后续被选中的概率（见 /health 与 /chat 返回中的 `routing_score`）。

## 9. 端到端评测

```bash
# 完整 94 条分层评测集（会真实调用 LLM + Judge，注意 API 额度）
curl -X POST http://localhost:8000/eval/run \
  -H "Content-Type: application/json" \
  -d @data/eval/creditlife_eval_cases.json

# 提交少量自定义用例
curl -X POST http://localhost:8000/eval/run \
  -H "Content-Type: application/json" \
  -d '{
    "intent_cases": [{"message": "我逾期了想协商还款", "expected_intent": "request"}],
    "dialog_cases": [{"question": "信用卡最低还款会影响征信吗？"}]
  }'
```

返回内容包括 `pass_rate`、五维平均分（相关性/准确性/完整性/有用性/**合规性**）、`regressions` 回归检测结果和 `recommendations` 优化建议。

评测集与结果说明：

- 评测集：`data/eval/creditlife_eval_cases.json`（94 条 = 意图 54：信用卡 30 + 贷后 24，分层易/中/难；对话 40：含催收红线对抗与带 expected_behavior 的危机干预用例）
- 标注规范：`data/eval/标注规范.md`；人工抽标表：`data/eval/人工抽标表.md`
- 最近完整轮结果：`data/eval/run_final.json`；多轮对比与归因见 `docs/评测报告.md`

## 10. 停止、重启和清理

```bash
docker compose stop          # 停止服务
docker compose restart creditlife  # 重启应用
docker compose down          # 停止并删除容器，保留数据卷
docker compose down -v       # 停止并删除容器和数据卷（清空记忆/知识库）
docker compose up -d --build # 重新构建并启动（改了 core/api 代码后需要）
```

Skills、知识库语料、评测集通过 volume 挂载，修改后无需重建镜像；`api/`、`core/`、`agents/` 等代码目录烘焙在镜像内，修改后需要 rebuild。

## 11. 常见问题

**/health 返回 503**
查看 `docker compose logs -f creditlife`。重点检查：.env 是否配置 ANTHROPIC_API_KEY、Redis/ChromaDB 是否健康、容器是否反复重启。

**ChromaDB 连接失败**

```bash
curl http://localhost:8001/api/v1/heartbeat
docker compose logs -f chromadb
```

**Redis 认证失败**
确认 .env 与 docker-compose.yml 中密码一致（默认 `creditlife123`）：`docker exec -it creditlife-redis redis-cli -a creditlife123 ping`

**Windows 命令行 curl 发中文变乱码**
Windows 控制台默认 GBK 编码，`curl -d '{"message":"中文"}'` 会把中文变成问号传给模型。解决：用调试前端（localhost:5173）、Swagger UI（localhost:8000/docs）发中文，或用 Python/Postman 发请求。

**/search 没有结果**
先 `GET /knowledge/stats` 确认有数据；为 0 时调用 `/knowledge/upload` 导入 `data/demo_docs/` 下的语料。

**用户画像 / 情景记忆查不到**
用户画像是异步更新的且依赖 LLM 调用成功（先多聊几轮、等几秒再查）；情景记忆要达到 15 条消息压缩阈值才写入。

**Docker Desktop 未启动（Windows）**
`docker ps` 报 `cannot find the file` 类错误时，先启动 Docker Desktop 再执行 compose 命令。
