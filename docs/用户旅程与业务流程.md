# CreditLife-Agent 用户旅程与业务流程

> 产品视角的流程资产：用户怎么用、系统怎么接、业务怎么流转、异常怎么兜底。
> 与 [架构图](架构图.md)（技术分层）互补——架构图回答"系统怎么组成"，本文回答"流程怎么走"。

## 1. 持卡人咨询旅程（User Journey）

```mermaid
journey
    title 一位逾期持卡人的咨询旅程
    section 触达
      收到账单/逾期提醒, 带着焦虑进线: 2: 持卡人
    section 发起咨询
      用口语描述困难: 3: 持卡人
      系统识别为逾期协商意图: 5: 系统
    section 澄清与方案
      补充卡号后四位与逾期天数: 4: 持卡人
      获得协商路径与材料清单: 5: 系统
    section 分叉
      标准协商: 5: 持卡人, 系统
      特殊困难需人工评估: 3: 持卡人, 人工客服
    section 收尾
      问题解决或转接成功: 5: 持卡人
      对话沉淀为画像与记忆: 4: 系统
```

旅程设计的两个产品判断：

- **情绪入口**：逾期用户进线时焦虑值最高，所以危机干预分支前置在路由最顶层（见 §3），先处理人、再处理事；
- **澄清成本**：结构化实体（卡号后四位/金额/天数）用规则抽取而非反复追问，减少一轮往返——每省一轮对话就是省一次 LLM 调用（见[指标体系与成本模型](指标体系与成本模型.md)）。

## 2. 服务蓝图（一次请求的前台与后台）

```mermaid
flowchart LR
    subgraph front["前台（用户可见）"]
        u1["输入问题"] --> u2["看到意图/路由面板"] --> u3["获得回复<br/>或转人工提示"]
    end
    subgraph mid["系统响应层（毫秒级）"]
        s1["记忆读取"] --> s2["意图识别"] --> s3["路由决策"] --> s4["Skills 注入 + RAG 检索"] --> s5["LLM 生成"]
    end
    subgraph back["后台支撑（用户不可见）"]
        b1["三层记忆读写"]
        b2["工具治理：缓存/熔断/降级"]
        b3["在线监控 + 路由降权"]
        b4["评测回归基线"]
    end
    u1 -.-> s1
    u3 -.-> b1
    s4 --- b2
    s5 -.-> u3
    back -.-> mid
```

## 3. 贷后核心业务流程：逾期协商

```mermaid
flowchart TD
    a0["逾期用户进线"] --> a1{"危机干预前置检查<br/>（确定性代码，不经 LLM）"}
    a1 -- "轻生/自伤表述" --> a1x["停止还款话题<br/>共情安抚 + 12356 热线 + 强制转人工"]
    a1 -- "未命中" --> a2["身份与账户核实<br/>（卡号后四位，不索要敏感信息）"]
    a2 --> a3{"逾期天数 / 状态分桶"}
    a3 -- "宽限期内" --> a4["还款提醒 + 最低还款/分期说明"]
    a3 -- "短期逾期 30-90 天" --> a5["协商路径：分期偿还 / 延期 / 利息违约金减免申请"]
    a3 -- "长期逾期 90 天以上" --> a6["说明法催与征信影响<br/>引导官方调解渠道"]
    a4 & a5 & a6 --> a7{"是否触及红线或超权限"}
    a7 -- "催收投诉 / 威胁恐吓指控" --> a8["催收投诉接待规范：<br/>记录 → 立即暂停该案催收动作 → 转人工专班"]
    a7 -- "承诺减免/洗白征信等违规要求" --> a9["明确拒绝 + 给合规替代路径"]
    a7 -- "正常范围内" --> a10["输出方案 + 材料清单 + 官方渠道"]
    a8 & a9 & a10 --> a11["沉淀画像与摘要，供下次进线续接"]
```

红线口径（GB/T 45251-2025、中银协催收指引）作为 Skill 规范注入，**不写死在代码里**——监管口径更新时热加载即可。

## 4. 合规拦截流程（三层兜底）

```mermaid
flowchart TD
    in["用户输入"] --> l1{"第一层：确定性拦截<br/>危机关键词（路由层最前置）"}
    l1 -- 命中 --> fix1["固定安全话术 + 12356 + 强制升级<br/>不经 LLM，行为 100% 确定"]
    l1 -- 未命中 --> l2{"第二层：规范注入<br/>Skill 红线 + RAG 红线手册"}
    l2 --> gen["Agent 生成回复<br/>（prompt 内含 15 条催收红线）"]
    gen --> l3{"第三层：事后评测<br/>LLM-as-Judge 合规维度"}
    l3 -- "触碰红线（0 分）" --> bad["进 badcase 归因：<br/>规范缺口 → 改 Skill / 改评测集"]
    l3 -- "合规" --> ok["正常返回"]
```

设计原则：**安全关键路径用确定性代码，概率性风险用评测兜底**——LLM 再好也不把轻生场景交给概率模型；而话术类合规（措辞越界）无法穷举拦截，靠 15 条红线量规持续评测。

## 5. 会话状态机

```mermaid
stateDiagram-v2
    [*] --> 新会话
    新会话 --> 澄清中: 信息不足
    新会话 --> 处理中: 意图明确
    澄清中 --> 处理中: 补齐关键实体
    处理中 --> 已回复: 生成完成
    处理中 --> 主辅并行: 复合问题
    主辅并行 --> 已回复: ResponseComposer 合并
    已回复 --> 澄清中: 追问新一轮
    已回复 --> [*]: 会话关闭(TTL 24h)
    处理中 --> 人工交接: 触发 handoff 条件
    澄清中 --> 人工交接: 用户主动要求
    人工交接 --> [*]
```

## 6. 工具熔断器状态机

```mermaid
stateDiagram-v2
    [*] --> closed
    closed --> open: 连续失败达到阈值
    open --> half_open: 冷却时间到期
    half_open --> closed: 试探调用成功
    half_open --> open: 试探调用失败
```

熔断的意义（对产品）：知识库抖动时用户拿到"降级回答 + 提示稍后再试"，而不是 30 秒超时白屏——**可用性优先于完整性**，这也是 Judge 完整性维度允许降级扣分而不算合规事故的原因。
