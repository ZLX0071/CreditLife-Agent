## 二、迭代内容与归因

**Run 1 → Run 2 的修复（badcase 归因驱动）：**

1. **「检索失败」根因修复（主要迭代）**
   - 现象：知识库 12 个向量片段就绪，但 `knowledge_search` 工具在对话中 0 触发，Agent 凭模型记忆裸答。
   - 归因：对照实验证明端点支持 tool_use（qwen-plus 裸上下文会正确返回 tool_use 块），问题出在提示层——工具描述仅"搜索知识库"无使用策略，且 Agent 系统提示词的工作流引导"直接回答"。
   - 修复：① 工具描述加入强制使用策略（业务事实问题先检索后回答，禁止凭记忆给具体数字）；② 系统提示词构建器新增全 Agent 通用[工具使用策略]段。
   - 验证：探针问题（争议交易流程）修复后 `knowledge_used: True`、工具 `search_knowledge_base` 被调用；评测耗时增加与每轮检索往返一致。

2. **意图模板补充（未达预期，如实记录）**
   - 现象：3 条意图误判——"办卡进度"×2 误判为 query（含 1 条 easy 层）、"重复扣款"×1 误判为泛化 billing。
   - 尝试：为 order_status / payment_issue 各补 3 条模板例句 → 两轮错误完全相同。
   - 结论：LLM+Embedding+Pattern 三路融合中，Embedding 分支为本地字符 n-gram 哈希向量，语义区分度不足；模板补充不足以扭转。**下一步**：在 Pattern 分支为"申请进度/办卡/审批"与"重复扣款/多扣"类表述增加确定性关键词规则（预期可修复 ≥2 例，抬升准确率至 93%+）。

## 三、能力亮点（面试可演示）

- **合规对抗 4/4 满分**：诱导推荐理财（拒绝+引导官方渠道）、承诺洗白征信（拒绝+告知征信条例）、指导以卡养卡（明确违规+解释风险）、施压承诺退息（拒绝+说明人工审核流程）——合规护栏在提示层真实生效，非评测放水。
- **回归检测闭环**：两轮均自动与基线比对，`regressions: []`，验证"可评测、可回归"的工程能力。

## 四、已知局限（诚实声明）

1. **Judge 宽松偏差**：LLM-as-Judge 与被测系统使用同一模型（qwen-plus），存在自偏好与宽谅偏差，绝对分数偏高（多维度 ≥0.98），维度间区分度被压缩。改进方向：换更强模型当 judge（如 qwen3-max）+ 定期人工标注校准（已预留校准说明）。
2. 意图 3 例误判未修复，已给出下一步方案（见二.2）。
3. 通过率 100% 部分源于 judge 宽松，不宜对外表述为"完美系统"；报告口径以维度分解 + 归因为主。
4. 业务口径（费率/天数）遵循"以领卡合同与官方公示为准"的保守表述，知识库语料为演示用通用口径，不对应任何真实金融机构。
