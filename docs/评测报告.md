> 评测集：`data/eval/creditlife_eval_cases.json`（94 条双业务线：意图 54 + 对话 40）
> 运行方式：`POST /eval/run` 全链路实测（意图识别 → 路由 → Agent 编排 → RAG → LLM-as-Judge 五维评分）

## 二、评测驱动迭代的三个实证案例

1. **RAG 检索 0 触发 → 修复**：基线发现知识库 12 个向量片段就绪但工具 0 调用。对照实验证明端点支持 tool_use，定位为工具描述无使用策略 + 系统提示词引导"直接回答"。修复后 RAG 正常触发（评测耗时 496s→608s 侧面证实），回归 0。
2. **意图 Pattern 层电商残留**：首轮双线评测意图 72.2%，归因发现 Pattern 规则字典仍是电商关键词（"订单状态/发货了吗"）。金融化强化（进度/放款/盗刷/催收/结清）后信用卡线错误 3→2，整体 72.2%→74.1%。
3. **降级行为观察**：免费额度耗尽导致 LLM 全部失败时，系统不崩溃、自动退化到向量+规则双路兜底继续答题（该轮已识别为无效数据并弃用）——为"系统韧性"提供了真实证据。

## 三、意图双口径说明（方法论）

94 条中贷后线含大量边界条目（如"协商还款"介于 request 与 billing、"投诉威胁"介于 complaint 与 escalation）。单标签口径对边界场景失真，故采用双口径：
- **严格单标签**：74.1% —— 14 个错误全部逐条归因（见 run 数据 metadata.cases）
- **意图组级**：77.8% —— 粗粒度组一致的即计正确
- 边界条目清单与判定规则见 `data/eval/标注规范.md` v1.2；**下一步**是 Pattern 规则继续强化 + 边界条目引入可接受标签集合。

## 四、Judge 校准（三层证据）

1. **双 Judge 对比**：qwen-turbo 独立复评 20 样本 vs 流水线 qwen-plus 评分，各维度偏差 ≤0.11，合规维度一致率 100%（`data/eval/judge_compare_result.json`）。
2. **人工抽标**：20 条（含全部对抗用例）人工五维打分 vs Judge，**±0.25 容差一致率 96%、精确一致率 50%、无方向性大分歧**；Judge 在 completeness 维度略严（人工 0.95 vs Judge 0.87），符合"Judge 偏保守"预期（`data/eval/human_agreement_result.json`）。
3. **已知局限**：主 Judge 与被测系统同系列模型，存在宽谅偏差；绝对分数偏高，评测价值在维度分解、对抗用例与归因，不在绝对分数。

## 五、诚实声明与数据披露

1. 模型切换：评测中途免费额度耗尽，自 qwen-plus 切换至同系列快照 qwen-plus-latest（质量档相同），最终轮与意图验证轮使用后者；两轮对话方差实验使用前者。
2. 品牌统一：项目更名后，历史评测记录（run_*.json）中的品牌词已随代码统一替换为 CreditLife（仅品牌 token，评分与文本内容未改动）。
3. 意图 14 个错误未全部修复，归因与下一步方案见第三节。
4. 业务口径（息费/利率/催收规范）为演示用通用表述，催收红线依据 GB/T 45251-2025 及公开报道口径，不对应任何真实金融机构。
