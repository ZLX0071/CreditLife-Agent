# CreditLife-Agent 架构图

> 使用 Mermaid 绘制，GitHub 原生渲染，随代码版本化维护。
> 配套阅读：[技术亮点](技术亮点.md)（每个设计解决什么问题）、[使用指南](使用指南.md)（怎么跑起来）。

## 1. 整体架构

```mermaid
flowchart TB
    user["用户 / 面试官"] --> ui["调试前端控制台<br/>localhost:5173"]
    user --> api2["Swagger / curl / SDK<br/>localhost:8000"]
    ui --> gw["Nginx 反向代理<br/>localhost:80"]
    api2 --> app["FastAPI 主应用<br/>creditlife-app"]

    gw --> app

    subgraph core["应用核心链路"]
        direction TB
        mem["MemoryManager<br/>三层记忆读写"]
        intent["IntentRecognizer<br/>三路融合意图识别"]
        orch["AgentOrchestrator<br/>路由决策 + 危机干预前置"]
        agent["四类 Agent<br/>账单/技术/综合接待/人工交接"]
        tools["MCPToolManager<br/>缓存/熔断/降级/重排"]
        kb["KnowledgeBase<br/>RAG 检索"]
        skills["SkillManager<br/>双业务线规范注入"]
        mem --> intent --> orch --> agent
        agent --> skills
        agent --> tools --> kb
    end

    app --> core

    subgraph storage["存储层"]
        redis[("Redis<br/>工作记忆 + 会话摘要")]
        chroma[("ChromaDB<br/>知识库 + episodic + user_profile")]
    end

    subgraph obs["观测层"]
        mon["PerformanceMonitor<br/>在线指标 + 路由降权"]
        prom["Prometheus<br/>localhost:9090"]
        ev["EndToEndEvaluator<br/>五维评测含合规"]
    end

    core --> storage
    core --> obs
    mon -. "monitor_penalty 回写路由" .-> orch
```

## 2. /chat 主链路

```mermaid
flowchart TD
    a1["1. 用户请求<br/>POST /chat"] --> a2["2. 读取记忆上下文<br/>Redis 工作记忆 + 情景记忆 + 用户画像"]
    a2 --> a3{"3. 危机干预前置检查<br/>（确定性代码，不经 LLM）"}
    a3 -- "命中轻生/自伤表述" --> a3x["固定分支：停止还款话题<br/>共情安抚 + 12356 热线 + 强制转人工"]
    a3 -- "未命中" --> a4["4. 三路融合意图识别<br/>LLM + Embedding + Pattern 投票"]
    a4 --> a5["5. 结构化路由决策<br/>primary + supporting + 置信度"]
    a5 --> a6["6. 主辅 Agent 并行执行<br/>按白名单调用工具"]
    a6 --> a7["7. 动态 Skills 注入 + RAG 检索<br/>查询改写 - 并行召回 - LLM 重排"]
    a7 --> a8["8. LLM 生成回复<br/>Prompt = 记忆 + 知识 + 实体 + Skills"]
    a8 --> a9["9. 返回 ChatResponse<br/>含 routing_reason / source_scores"]
    a9 --> a10["10. 异步后处理<br/>写回工作记忆 + 更新用户画像"]
    a10 --> mon2["Monitor 采集指标<br/>表现差 - monitor_penalty 降权"]
```

## 3. 双业务线 Skill 注入

```mermaid
flowchart LR
    m["用户消息"] --> s["SkillManager<br/>关键词 + Agent 类型匹配"]
    s -- "分期 / 账单 / 息费 / 积分" --> card["信用卡业务线"]
    s -- "逾期 / 协商 / 催收 / 投诉" --> loan["贷后业务线"]
    s -- "App 报错 / 登录异常" --> tech["通用技术支持"]

    card --> c1["银行卡综合服务接待规范"]
    card --> c2["账单服务处理规范"]
    loan --> l1["贷后还款与逾期协商规范<br/>含催收红线手册（GB/T 45251-2025 口径）"]
    loan --> l2["借款咨询与催收投诉接待规范"]
    tech --> t1["技术支持处理规范"]

    c1 & c2 & l1 & l2 & t1 --> p["注入对应 Agent 的 system prompt<br/>上限 8000 字符，热加载生效"]
```

> 关键词在信用卡线与贷后线之间严格切分，同一句"还款"按上下文命中不同规范、互不污染。


## 5. 监控与评测闭环

```mermaid
flowchart LR
    subgraph online["在线监控链路"]
        o1["对话请求<br/>POST /chat"] --> o2["Agent 编排器<br/>成功率 / 延迟 / 路由评分"]
        o2 --> o3["工具管理器<br/>缓存 / 熔断 / fallback"]
        o3 --> o4["PerformanceMonitor<br/>异常检测 + 告警 + 建议"]
        o4 -- "monitor_penalty" --> o2
        o4 --> o5["Prometheus / metrics"]
    end

    subgraph eval["离线评测链路"]
        e1["评测请求<br/>POST /eval/run"] --> e2["94 条分层用例<br/>真实调用生成回复"]
        e2 --> e3["LLM-as-Judge 五维评分<br/>相关性/准确性/完整性/有用性/合规性"]
        e3 --> e4["回归检测 + 优化建议"]
        e4 --> e5["三层校准<br/>双 Judge 交叉 + 20 条人工抽标(96%) + 基线回归"]
    end
```

> 两条链路共同保证：路由不靠静态配置，评测不靠感觉——在线表现反哺路由选择，离线评测量化每一次迭代。
